# experiments/global: shared code and the cross-model comparison

Everything that more than one experiment uses, i.e. everything before an experiment's differentiating point, plus the
comparison across experiments. Nothing in here is specific to one model.

| Path | What |
|---|---|
| `mrc/paths.py` | Project paths. Import from here instead of counting parents of `__file__` |
| `mrc/prepare_data.py` | The grouped train/dev/itest split (seed 13), with hashes in `data/splits/hashes.json` |
| `mrc/evaluate.py` | The SQuAD v2 evaluator (EM, F1, HasAns, NoAns, threshold search; refuses threshold search on test files) |
| `mrc/qa_text.py` | Tokenizer, light stemmer, sentence splitter and question types (used by 01 and 02) |
| `mrc/llm_qa.py`, `mrc/llm_api.py` | LLM harness: prompts, parsing, grounding, na_prob; local and API backends (used by 05 and 06) |
| `mrc/eval_order.py` | One fixed question order per split (global seed 13, stratified by answerability) for partial and resumable runs |
| `mrc/analysis/slices.py` | Slice tags for every question (`data/processed/slices_*.jsonl`) |
| `mrc/analysis/experiment.py` | The error analysis every experiment's `analyze.py` runs (dev by default; `split_file=` for official_val) |
| `mrc/analysis/compare.py` | Cross-model comparison -> `report/assets/tables`, `report/assets/figures` |
| `mrc/analysis/per_example.py` | One record per dev question with every model's prediction (feeds `eda/notebooks/model_errors.ipynb`) |
| `mrc/make_submission.py` | Leaderboard CSV (`id,answer`, empty = no answer) from one run, threshold tuned on official_val |
| `mrc/analysis/official_val.py` | Official validation table: as predicted vs dev-tuned vs val-tuned threshold -> `report/assets/tables/official_val_table.md` |
| `mrc/final_test_eval.py` | The single sealed evaluation on itest (needs `--confirm`, checks the split hash) |
| `configs/models_registry.yaml` | Which run folders the cross-model comparison reads |
| `configs/llm_prompts.yaml` | LLM prompts `id1`..`id5` and `en1` |
| `requirements.txt` | pip fallback exported from the root `uv.lock` (prefer `uv sync`, see the root README) |
| `run.py` | Runs any `mrc` module from anywhere |

## Running
```
uv sync                                                            # once, from the project root
python experiments/global/run.py mrc.prepare_data                  # split (already done; deterministic)
python experiments/global/run.py mrc.analysis.slices               # slice tags
python experiments/global/run.py mrc.analysis.compare              # cross-model tables and figures
python experiments/global/run.py mrc.analysis.per_example          # per-question file for the error browser
python experiments/global/run.py mrc.evaluate --gold data/processed/dev.jsonl --pred <preds.jsonl> --na-threshold-search
python experiments/global/run.py mrc.analysis.official_val          # official validation table (needs preds_official_val.jsonl)
python experiments/global/run.py mrc.make_submission --run <run dir> --split-file data/processed/official_test.jsonl \
    --threshold-from official_val --out submissions/<model>_<seed>.csv
```
Relative paths in arguments resolve from the project root, whatever the current folder is. On Windows set
`PYTHONIOENCODING=utf-8` if the console shows encoding errors.

## Experiment folders
Name: `NN-<scope>-<name>`, extended as `NN-<scope>-<subscope>-<name>[-<subname>]` when a scope has several levels.
The scope is what the experiment varies: model family here, or later `tokenizer`, `embedding`, `prompt` and so on.
Examples: `03-nn-bidaf`, `05-llm-local-qwen`, a future `07-tokenizer-bpe` or `08-plm-xlmr-lora`. Numbers only order
folders and are never reused.

Each experiment owns its work end to end, from its differentiating point to its error analysis:
```
experiments/NN-<scope>-<name>/
  summary.md     the whole view: differentiating point, pipeline + commands, design, results, error analysis,
                 findings, open questions (section 4 is generated by analyze.py; the rest is written by hand)
  *.py           the code that is specific to this experiment (model, features, training, prediction)
  analyze.py     last stage: calls mrc.analysis.experiment.analyze() on its runs
  runs/<variant>/<seed>/   config.json, preds_dev.jsonl, metrics_dev.json, log.txt (written by the training code)
  analysis/      written by analyze.py
```
Every experiment script starts with a two-line bootstrap that puts `experiments/global` on `sys.path`, so `import mrc`
works whatever the current folder is. Copy it from any existing script.

### Adding an experiment
1. Create `experiments/NN-<scope>-<name>/` and copy `summary.md` and `analyze.py` from the closest existing experiment.
2. Write predictions in the run format above (any model; `preds_dev.jsonl` lines need `id`, `pred`, and `na_prob` if
   the model has a no-answer score).
3. Set `VARIANTS` in `analyze.py` and run it.
4. To include it in the cross-model table and the error browser, add its run glob to `configs/models_registry.yaml`
   (`order` and `models`), then rerun `mrc.analysis.compare` and `mrc.analysis.per_example`.
